# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Readme Studio turns one `readme.config.json` into an animated, self-updating GitHub README: a profile README (`<login>/<login>`) or a project README (any public repository). The studio (`apps/web`, https://readme.niessen.dev) designs it. The GitHub Action (`DavidNiessen/readme-studio@v1`, `action.yml`) re-renders it on a schedule in the user's repository. Both call the same renderer, so the studio preview and the published images match byte for byte.

## Commands

npm workspaces; Node 22 (`.nvmrc`).

```bash
npm ci
npm run dev                  # studio at http://localhost:5173
npm test                     # vitest: packages/*/test and apps/web/test
npx vitest run packages/engine/test/project.test.ts            # one file
npx vitest run packages/engine/test/project.test.ts -t "full releases"   # one test by name
npm run typecheck            # every workspace
npm run bundle               # rebuild packages/engine/dist (the action and CLI run the committed bundle)
npm run build                # studio build; first regenerates apps/web/public/{schema,widgets,presets}.json and llms*.txt
npm run extension            # browser extension → apps/extension/dist/{chrome,firefox} + zips
npm run example              # render examples/readme.config.json with mock data → examples/dist/preview.html
npx tsx scripts/preview-widgets.ts /tmp/sheet crimson dark jetbrains-mono [project]   # contact sheet of every widget
node packages/engine/dist/cli.mjs --help   # CLI: init, validate, build, link, widgets, presets, themes, schema
```

CI (`.github/workflows/ci.yml`) runs `typecheck`, `test`, `bundle` and fails if `packages/engine/dist` changed, `build`, and the action itself (`uses: ./`, mock + dry-run). The release workflows call it through `workflow_call`.

## Architecture

**`packages/core`** is isomorphic (no Node APIs). Everything that decides what a README looks like lives here.

- `config.ts`: `StudioConfig` (`kind` profile|project, `profile`, `project`, `theme`, `layout` rows of blocks, `output`). `normalizeConfig` repairs any input and never throws: it returns the config plus warnings, which the CLI's `validate` reports. A new config field needs the normaliser, `jsonschema.ts` (published as `schema.json`), and usually the studio inspector.
- `widgets/`: each widget is a `defineWidget({ type, scope, kind: svg|gif|markdown, width, defaults, fields, render })`, registered in a `set-*.ts` list. `fields` drive the studio inspector, the docs, `widgets.json` and `llms-full.txt`. Multi-image widgets (shields, socials) define `parts`/`renderPart`, one image per part so each can link elsewhere. `scope` limits a widget to profile or project READMEs.
- `render.ts`: `createCtx` → `layoutParts` → `renderPart`/`renderFrames`. `readme.ts` `renderReadme` writes the README: `<picture>` with dark/light sources per row, Markdown blocks verbatim, and a banner comment linking `#/studio?repo=…`.
- `theme.ts`: palettes and `resolvePalette` (preset or `accent`-derived, then per-mode `overrides`). `fonts/` holds base64 woff2 plus glyph `metrics.ts`. Text is measured with `textWidth`/`fitText`/`wrapText`, never assumed monospace. Fonts and icons are generated by `scripts/build-assets.ts` and committed. Icons: brands in `icons/data.ts` (every bundle) and `icons/more.ts` (on demand: `loadMoreIcons`, which the action, the CLI, the studio and `scripts/schema.ts` call first), and Lucide line icons in `icons/lines.ts`, drawn like the hand-drawn glyphs through `glyph()`. Render caches key on `iconsVersion()`.
- `data/`: `live.ts` fetches profile data (GraphQL with a token, else REST plus the scraped calendar). `project.ts` fetches a repository: stars, contributors with data-URI avatars, commit activity, releases (pre-releases are dropped once a full release exists), CI (skips the README workflow's own runs), milestones, npm/PyPI/crates downloads. `mock.ts` is the deterministic sample data used by `--mock`, tests and the studio.
- `presets.ts` (profile and project presets), `workflow.ts` (`workflowYaml`, `ACTION_REF` = `@v1`, `STUDIO_URL`), `catalog.ts` (`llms.txt`, the widget/preset catalogs).

**`packages/engine`** is Node only.

- `build.ts`: loads data and renders every part to files, plus `README.md`, `preview.html` and `data.json`. GIFs are rasterised with resvg in `raster.ts`.
- `action.ts`: the action entry point. It publishes only on the repository's default branch (`branch.ts`); pull requests and other branches render only.
- `publish.ts`: force-pushes the assets to an orphan asset branch (default `readme-studio`), then commits `README.md` with `[skip ci]` only when it changed.
- `cli.ts`: everything the studio does, scriptable. `--json` gives machine-readable output, and `link` encodes a share token.
- `dist/{action,cli}.mjs` are self-contained esbuild bundles (`scripts/bundle.ts`). **Commit them whenever core or engine changes.** Users' workflows run them straight from the `v1` tag.

**`apps/extension`**: Manifest V3 extension for Chrome and Firefox, built by `scripts/build.ts` (Vite: two pages, an IIFE content script and background script, icons, a manifest per browser from `src/manifest.ts`, zips).
- It reuses the studio instead of copying it: `apps/web` exports the studio, store, UI kit and styles (`package.json` `exports`), and `src/studio/main.tsx` mounts `Studio` with a `StudioHost` (`apps/web/src/studio/host.ts`: `open`, `github`, `actions`, `overlays`, `onClose`, `context`, `siteUrl`, `failed`). Put studio features in `apps/web`; only what needs the extension (the content script, device flow, extension storage) belongs in the extension.
- `src/content/github.ts` adds the "Edit README" / "Design README" button (shadow DOM) on repository pages (found through the `octolytics-dimension-repository_nwo` meta tag), shows `studio.html#repo=owner/name` in an iframe inside an overlay panel (backdrop click or Esc closes it), and fills GitHub's editor for the no-sign-in save mode.
- Drafts: the host's `open()` returns `source: "github:owner/repo"`; the studio store keeps one saved design per source (`openSource`) with the `base` it started from, so unsaved work survives closing, each repository has its own, and a draft whose repository changed since is flagged.
- Save to GitHub is shared: `apps/web/src/github/` (REST client: inject `fetch` in tests, never store `fetch` as a method, browsers throw "Illegal invocation"; opening, importing a README, saving) and `apps/web/src/studio/github/` (dialog, sign-in, session). A `GitHubPlatform` (`github/platform.ts`) supplies what differs: the website's `webPlatform` (token only, clipboard for GitHub's editor) and the extension's `src/studio/githubPlatform.ts` (device flow in `src/github/auth.ts`, extension storage, the content script fills GitHub's editor).
- Versions: `RS_VERSION` sets the build version; pre-releases `x.y.z-n` become manifest `x.y.z.n`.

**`apps/web`**: React 19 + Vite + zustand (`state/store.ts`, designs saved in localStorage).

- Hash routing with a relative Vite `base` (`./`), so the same build works on the custom domain and on a sub-path. Don't make `base` absolute.
- Studio deep links: `#/studio?repo=owner/name` loads that repo's committed config from raw.githubusercontent, `?config=<url>`, `?design=<base64url(zlib(json))>` (the same format as the CLI's `shareToken`), and `?preset=<id>`.
- `studio/Canvas.tsx` renders the preview through `lib/render.ts`, with the same core calls as the action. Markdown blocks go through `lib/repoLinks.ts`, so relative images and links resolve against the design's repository.

## Conventions

- **Widget house style:**
  - use `card()` for surfaces;
  - escape every user or data string with `esc`;
  - give ambient loops the `loop` class so motion levels and `prefers-reduced-motion` apply;
  - keep SVGs well under 1.5 MB;
  - render well with empty and hostile data, because the tests feed both.
- After changing widgets, options or presets, run `npm run build` (or `npx tsx scripts/schema.ts`) so `apps/web/public/*.json` and `llms*.txt` stay current. They are committed.
- **Commits:** Conventional Commits (`feat(core): …`, `fix(web): …`, `ci: …`). Interface and docs text is plain and specific; comments say why.
- **Releases:**
  - Every push to `main` publishes a pre-release (`x.y.(z+1)-RUN`; the newest three are kept).
  - Full releases are run by hand: Actions → Release, with a `patch`/`minor`/`major` bump or an exact version (`scripts/set-version.mjs`). A full release moves the floating `v1` tag that users' workflows pin.
  - A fix to the action or renderer reaches users only after a full release.
  - `pages.yml` deploys the studio on every push to `main`.
  - Pre-releases and releases attach the extension zips; a full release also publishes to the Chrome Web Store / Firefox Add-ons when their secrets exist, and skips that otherwise.
